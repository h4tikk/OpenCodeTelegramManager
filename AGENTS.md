# Правила разработки OpenCode Telegram Manager

- Общение, README и описания изменений — по-русски. Следуйте явным указаниям владельца.
- .NET 10/C# 14, nullable, async + CancellationToken. Telegram — транспорт; бизнес-логика в Application, файловые операции/API/EF — Infrastructure.
- Проверяйте реальный OpenCode v2 contract перед изменением endpoints/DTO. Не применяйте v1 endpoints к v2. Не читайте внутреннюю БД OpenCode.
- Не выполняйте реальные платные запросы в автоматических тестах. Live smoke — только временная сессия, resume=false, отмена inbox и архивирование.
- Каждое действие Telegram: User ID, private Chat, Chat ID; callback авторизуется отдельно. Никакой авторегистрации первого пользователя.
- Секреты, SQLite и пользовательские вложения не должны попадать в Git, Docker image или логи. `.env` игнорируется, `.env.example` не содержит значений.
- Не повторяйте POST промпта после неопределённого ответа. Сохраняйте попытку до запроса, используйте NeedsReconciliation и проверяйте свой message ID.
- IDbContextFactory: отдельный DbContext на операцию. Не используйте один контекст из нескольких потоков. Не редактируйте применённые миграции, добавляйте новые.
- Файловая система — источник дерева каталогов. Не создавайте Project для каждой папки и не сканируйте домашний каталог рекурсивно.
- Канонизируйте пути и symlink, проверяйте компонентные границы, регистр Linux. Не обещайте защиту от TOCTOU только средствами System.IO.
- Проверяйте файл непосредственно перед передачей. Не распаковывайте ZIP в проект и не исполняйте вложения. Перезапись — только явным scoped подтверждением.
- OpenCode/VPN остаются на хосте; менеджер — в Compose host networking. Не монтируйте /home, /, SSH, VPN или Docker socket. Не создавайте дубли polling или серверов.
- Без отдельной проверенной изоляции OpenCode не расширяйте автоматические shell-разрешения. AGENTS.md не является sandbox.
- После логического этапа: build, относящиеся к изменению тесты, затем отдельный коммит с текущим авторством владельца. Не push.
- Не перезапускайте весь Docker daemon, VPN или ПК ради тестов без отдельной оценки влияния и разрешения.

- Автономный профиль: только отмеченные manager-сессии; host-адаптер в deploy/autonomy. Изменения политики проверяйте Node/Python тестами, не добавляйте fallback на неизолированный shell.
