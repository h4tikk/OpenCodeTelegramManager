# Диагностика

- Контейнер healthy, но бот молчит: healthcheck проверяет процесс. Настройте Telegram__Token и BotSecurity__OwnerUserId, пересоздайте/перезапустите контейнер, напишите `/start` в личном чате. Чужие аккаунты и группы молча игнорируются.
- HTTP 401 OpenCode: пароль service.json изменён; повторно импортируйте его в защищённый env. Не печатайте файлы с секретами в issue или логи.
- HTTP 429/403 модели: наличие в каталоге не доказывает оплату/доступность. Выберите доступную модель и создайте новую задачу после сверки старой. Автоматическое переключение модели в неизвестной операции не выполняется.
- NeedsReconciliation: приложение не знает, был ли принят промпт, либо в сессию пришёл внешний ввод. Проверьте историю/inbox через OpenCode UI/API. Автоматического повторного POST и безусловного снятия блокировки нет. Не запускайте ту же изменяющую задачу повторно до сверки.
- Нет папки: проверьте bind mount и разрешённый корень, реальный canonical path и права UID/GID. За границы корней через symlink выйти нельзя в обычном сценарии, но полная защита от конкурентной смены symlink требует kernel-level ограничений.
- Файл не скачивается: имя/содержимое может подпадать под политику секретов, размер превышать лимит, либо файл удалён. Политика не обходится кнопкой «скачать».
- Изображение отклонено: проверьте формат/размер и image input выбранной модели. Header check не равен полному безопасному декодированию, OpenCode/Telegram дополнительно валидируют файл.
- Ошибка PDF: отсутствующий/зашифрованный/повреждённый PDF или скан без текста не выдаётся за успешно распознанный. OCR не реализован.
- После падения при передаче: исходящая передача не переотправляется автоматически; запросите файл заново. Передача и задача — разные сущности.
- Ошибка БД locked: проверьте второй менеджер. Дополнительно к SQLite timeout действует file lock. Не удаляйте WAL/SHM при работающем приложении.
- OpenCode недоступен после загрузки: `systemctl --user status opencode`, `loginctl show-user hatikk -p Linger`. Drop-in наблюдает существующий сервер, сохраняя активные сессии; при его штатном выходе включает обычный launcher. Не запускайте standalone-сервер рядом с shared.
- VPN: менеджер не меняет маршруты и не включает резервный прямой прокси. Фоновый reconnect сохраняет очередь. Реальное отключение VPN и restart всего Docker daemon не выполнялись, чтобы не нарушить другие процессы.

```bash
docker compose logs --tail=100
docker compose exec opencode-manager dotnet OpenCodeManager.Worker.dll --doctor
docker compose exec opencode-manager dotnet OpenCodeManager.Worker.dll --health
python scripts/verify-compose.py
```

Для резервной копии используйте SQLite backup API (`sqlite3 manager.db '.backup /safe/path/manager-backup.db'`) или остановите контейнер и копируйте каталог целиком. Не копируйте только main db при активном WAL. Восстановление — при остановленном контейнере с сохранением UID/GID и permissions.
