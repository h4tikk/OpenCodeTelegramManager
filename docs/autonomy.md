# Автономная работа

По умолчанию `Autonomy__Enabled=true`. Менеджер до отправки задачи проверяет активный плагин `opencode.manager.autonomy.v1`, затем сохраняет метаданные с каноническим рабочим каталогом. Плагин меняет разрешения и shell только для отмеченных сессий и их дочерних агентов. Обычные сессии пользователя сохраняют свою политику.

## Решения без диалогов

Чтение, поиск и правка допустимых файлов проекта разрешаются автоматически. Shell автоматически оборачивается изолированным исполнителем. Явный deny не переопределяется. Внешние пути, секреты, конфигурация плагинов, привилегированные действия, push, разрушительные команды БД и неизвестные инструменты получают отказ. Агент получает объяснение и должен сообщить реальный блокер, если не может продолжить. Менеджер не повторяет промпт ради обхода отказа.

## Shell

Нужен установленный на хосте `bubblewrap` (`/usr/bin/bwrap`), Python 3 и поддержка user namespaces. `python scripts/install-autonomy.py` устанавливает:

- `~/.config/opencode/plugins/opencode-manager-autonomy/index.ts` — плагин OpenCode v2;
- `~/.local/lib/opencode-manager-autonomy/` — отдельные модули и настройки;
- резервные копии прежней установки — `~/.local/state/opencode-manager/autonomy-backups/`.

Установщик читает `.env` (или файл `Manager__EnvironmentFile`) как данные; переменные окружения имеют приоритет. Корни берутся из `Projects__AllowedRoots__N` либо `MANAGER_PROJECTS_ROOT`, read-only кэши — из `Autonomy__ReadOnlyCaches__N`, путь NuGet packages — из `Autonomy__NugetPackages`. Личные пути не зашиты в коде. После изменения этих параметров повторите установку плагина. Новый сервер OpenCode не нужен; активацию плагина менеджер проверяет через публичный `/api/plugin`.

На каждый shell-вызов создаётся ограниченная копия выбранного проекта: максимум 100000 файлов / 512 MiB. Bubblewrap отделяет PID, сеть и окружение, убирает capabilities, предоставляет read-only `/usr`, временные home/tmp, только выбранный проект и явно заданные read-only кэши NuGet/Cargo registry. Не передаются host environment, токены, SSH и пользовательские конфиги. Существующие SQLite-файлы доступны только на чтение, Git metadata — на чтение с отключёнными hooks/fsmonitor. Команда ограничена 10 минутами; фоновые host-команды не запускаются.

Обычные изменённые/новые/удалённые файлы возвращаются в проект с проверкой исходных хешей. Символические ссылки, секреты, БД и конфигурация OpenCode не возвращаются. Неизменённые файлы не перезаписываются. Это защищает от обнаруженных конкурентных изменений, но не обеспечивает транзакцию всего дерева или полной защиты от TOCTOU. Нельзя считать весь host OpenCode изолированным: нативные инструменты, плагины и сервер продолжают работать с правами пользователя. Фильтрация секретных имён остаётся эвристикой. Не отмечайте недоверенные проекты как доверенные.

Shell не имеет сети. Новые зависимости, удалённые сервисы, Docker daemon и интеграционные тесты с ними могут быть недоступны; отсутствие кэшированного пакета — реальный блокер. Большой проект может превысить лимиты копии. Обычные compile/test с доступными зависимостями работают без вопросов. Не ослабляйте профиль глобальным `shell: allow`.

## Проверки и управление

`dotnet test` запускает также Node-тест политики и Python-тесты настоящего sandbox из `tests/autonomy/`. Для них нужны Node.js, Python 3 и bubblewrap на машине тестирования. Платные запросы и реальные проекты пользователя в тестах не используются.

Чтобы вернуть ручные подтверждения, укажите `Autonomy__Enabled=false` в защищённом env-файле и выполните `docker compose restart`. При старте менеджер обновляет метаданные активных задач; при следующей отправке обновляется выбранная сессия. Уже помеченные неактивные сессии сохраняют профиль до следующей отправки через менеджер. Плагин не меняет глобальные разрешения OpenCode.
