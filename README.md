# OpenCode Telegram Manager

Локальный менеджер OpenCode v2 для одного владельца Telegram. OpenCode и VPN работают на Arch Linux, Worker — в Docker с сетью хоста. Код .NET 10/C# 14, EF Core 10 + SQLite, Telegram.Bot, типизированный REST-клиент и SSE.

## Быстрый запуск

Рабочее развёртывание настроено в этом каталоге. `.env` — игнорируемая Git ссылка на `~/.config/opencode-manager/manager.env` (0600). В Git лежит только `.env.example`. Токены не входят в образ, SQLite или логи.

Один раз создайте бота в BotFather, узнайте свой числовой Telegram User ID и выполните:

```bash
python scripts/configure-secrets.py
```

Скрипт скрывает ввод токена, проверяет `getMe`, записывает защищённую конфигурацию и пересоздаёт контейнер. Не вставляйте токен в сообщения, командную строку или Git. ID задаётся явно; первый написавший боту не становится владельцем. После запуска откройте личный чат бота и `/start`.

Без токена/ID контейнер работает в режиме ожидания: polling и очередь не запускаются. После изменения файла конфигурации нужен `docker compose restart` или запуск скрипта настройки. Пересборка не нужна.

```bash
docker compose up -d
docker compose down
docker compose restart
docker compose logs -f
docker compose ps
```

Для сборки после изменения исходников: `docker compose up -d --build`. Не используйте `down -v` для обычного обслуживания. Данные — bind mount, не анонимный Docker volume.

## Хранение и доступ к файлам

- `/mnt/data/Projects` смонтирован в ту же абсолютную директорию, доступ на запись от UID/GID 1000:1000.
- `~/.local/share/opencode-manager` смонтирован в тот же абсолютный путь: `manager.db`, `uploads/`, `downloads/` и метаданные.
- Конфигурация монтируется read-only в `/run/secrets/manager_env`.
- Весь `/home`, SSH, VPN-конфигурации и Docker socket не монтируются. Root filesystem контейнера read-only, capabilities удалены.
- Файловая система — источник структуры папок. SQLite хранит только зарегистрированные корни, избранное/недавние, открытые проекты и сессии. Вложенное дерево не сканируется при запуске.

Кнопка «Файловый менеджер» открывает корни. Переходы, страницы, избранное и недавние папки редактируют одно сообщение. «Открыть эту папку» запрашивает реальные сессии OpenCode. «Новая сессия» создаёт независимую сессию с выбранной рабочей директорией, без нативного parentID для смены каталога.

«Файлы» → файл → скачать оригинал, предпросмотр, добавить к задаче. Можно выбрать несколько файлов, скачать выбранные или создать ZIP. «Создать папку» принимает только один безопасный компонент имени. Поиск по имени работает в текущем каталоге.

Загрузка с телефона сначала попадает в постоянное временное хранилище. Кнопки позволяют добавить файл к задаче, сохранить в текущей папке браузера, выбрать папку или удалить временную копию. Перезапись существующего файла требует отдельного одноразового подтверждения с зафиксированной папкой. ZIP никогда автоматически не распаковывается.

Фото Telegram приходит в сжатом Telegram виде. Чтобы сохранить оригинальное изображение, отправляйте его как Document. PNG/JPEG/WebP/GIF определяются по сигнатуре и заголовку размера, ограничены числом пикселей. Оригинал не преобразуется. Для AI используется проверенный OpenCode v2 `files[].uri` (data URI), а не контейнерный путь. Изображения допускаются только для модели, объявляющей image input. PDF передаётся в поддерживаемый загрузчик OpenCode; DOCX и текст извлекаются локально с лимитами. Извлечение текста из PDF без OCR — через `pdftotext`.

Лимиты по умолчанию: входящий файл 5 MiB, исходящий 49 MiB, ZIP 40 MiB исходных данных, 1000 файлов/каталогов, глубина 12, 30 секунд, 40 млн пикселей, до 10 вложений и 20 выбранных файлов. Пересечение лимита отменяет операцию и удаляет частичный ZIP. Секретные имена/каталоги и распространённые plaintext credentials исключаются; это эвристика, не полноценный DLP. Содержимое исходных файлов в SQLite не копируется; промпты/ответы задач хранятся как пользовательские данные. Бинарные данные — только на диске.

После задачи «Файлы результата» показывает файлы из снимков OpenCode, реально существующие на диске. Выберите конкретные файлы для скачивания/ZIP: общий Git diff пользователя автоматически в архив не попадает.

## Задачи и разрешения

Выберите проект/сессию, модель и агента, нажмите «Новая задача» и отправьте текст или файл с подписью. Настройки задачи сохраняются в момент постановки. Статусное сообщение обновляется с ограничением частоты, итог/логи/diff доступны кнопками. Остановка — в карточке задачи; `/cancel` сбрасывает только ввод.

SQLite — долговременная FIFO-очередь. До POST сохраняется отдельная попытка с уникальным message ID. Не более двух активных задач и одной на Git-дерево, включая общий gitdir worktrees. После сбоя `Dispatching` становится `NeedsReconciliation`: менеджер ищет свой message ID в истории и inbox. Неопределённый POST не повторяется. Завершение требует собственного сообщения и последующего idle marker, а не старого outcome сессии. Чужой промпт в том же turn блокирует автоматическое завершение. REST регулярно сверяет состояние, поскольку SSE не гарантирует доставку.

Чтение/правка конкретных безопасных файлов внутри проекта подтверждаются автоматически. Shell, sudo, push, операции над БД и неизвестные инструменты требуют разрешения. Ограниченное постоянное правило разрешено только для безопасных точных файлов сессии; native `always` не используется. Молчание не считается согласием.

**Полная автономная сборка/отладка в shell пока не включена.** OpenCode работает на хосте от владельца и не изолирован контейнером менеджера. Для автоматического разрешения произвольного build/test-кода требуется отдельный проверенный sandbox исполнителя. AGENTS.md и проверка путей не являются такой изоляцией. Глобальные разрешения OpenCode не меняются.

Лимиты выполнения: 60 минут и 200 наблюдённых вызовов инструментов. В промпте указан максимум 8 циклов проверки; это инструкция агенту, а не доказанный счётчик запусков тестов. Жёстко ограничиваются время и число событий вызовов инструментов. Ни проценты, ни успешные проверки не выдумываются.

## Команды Telegram

| Команда | Назначение |
|---|---|
| `/start` | Главное меню |
| `/help` | Справка |
| `/status` | Реальные API, SQLite и dispatcher |
| `/projects` | Категории и открытые проекты |
| `/sessions` | Синхронизированные сессии |
| `/tasks` | Очередь и история задач |
| `/models` | Каталог моделей; генерация не проверяется |
| `/agents` | Доступные primary/all агенты |
| `/files` | Файловый менеджер |
| `/cancel` | Сбросить ввод и ожидающие вложения |

## Архитектура и разработка

```text
src/OpenCodeManager.Domain          сущности и статусы
src/OpenCodeManager.Application     сервисы, очередь, разрешения, интерфейсы
src/OpenCodeManager.Infrastructure  EF Core, API, System.IO, архивы
src/OpenCodeManager.Telegram        Telegram.Bot, меню, файлы
src/OpenCodeManager.Worker          DI, конфигурация, фоновые сервисы
tests/                             unit и integration tests
deploy/                            сопровождение OpenCode на хосте
docs/                              контракты, настройки, диагностика
```

```bash
dotnet restore
dotnet build
dotnet test
dotnet tool restore
dotnet ef migrations add Name --project src/OpenCodeManager.Infrastructure --output-dir Persistence/Migrations
dotnet run --project src/OpenCodeManager.Worker -- --migrate
dotnet publish src/OpenCodeManager.Worker -c Release -o .artifacts/publish
```

Миграции автоматически применяются при штатном старте. Для локальных команд передайте `Manager__EnvironmentFile=/home/hatikk/.config/opencode-manager/manager.env`. Для doctor из работающего контейнера:

```bash
docker compose exec opencode-manager dotnet OpenCodeManager.Worker.dll --doctor
python scripts/verify-compose.py
python scripts/verify-opencode.py
```

Последний скрипт создаёт только временную сессию, проверяет SSE и image admission с `resume=false`, отменяет inbox и архивирует сессию; платной генерации нет. Автоматические .NET-тесты используют mocks и временные каталоги.

## Автозапуск

Docker Engine уже enabled. Compose использует `restart: unless-stopped`, отдельного systemd unit менеджера нет. Существующий `opencode.service` включён в user systemd, Linger для `hatikk` включён с разрешения владельца. Drop-in `manager-supervision.conf` отслеживает существующий shared server, не прерывая активные сессии, и запускает обычный launcher после его выхода. После новой загрузки запускается обычный OpenCode. Текущий работающий процесс не дублируется. Успешная загрузка ПК без входа не проверялась фактической перезагрузкой.

```bash
systemctl --user status opencode
journalctl --user -u opencode -f
loginctl show-user hatikk -p Linger
```

Сеть контейнера совпадает с хостом. Прокси/VPN в контейнере не настраиваются, OpenCode остаётся на `127.0.0.1:49374`. Порт наружу не публикуется. Временные сбои API и Telegram обрабатываются повторным подключением; неопределённые промпты не переотправляются. Healthcheck проверяет heartbeat Worker, а не наличие токена или доступность модели.
